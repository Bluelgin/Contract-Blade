# 契约武器压力测试 — 2026-10-04

## 结论

分批恢复有效限制单次处理工作量，但没有限制待恢复快照的累计内存。
在本次隔离测试中确实触发了 Java 堆内存耗尽，并导致部分服务器后台线程失效。
不能把当前实现描述为“已经彻底防住恶意堆叠导致的崩服”。

不存在适用于所有服务器的固定武器数量阈值。数据量、对象布局、垃圾回收器、
其他模组和可用内存都会改变阈值。本报告仅记录本次条件下的观察。

## 环境与负载

- Windows，Microsoft Java 17.0.20.1，Forge 47.4.10，Minecraft 1.20.1。
- 契约之刃当前本地分支，Touhou Little Maid 1.5.3；未加载拔刀剑等额外联动。
- 隔离服务器最大 Java 堆：1024 MiB，测试前堆使用约 284–290 MiB。
- 测试目录 `run-native-home-validation`，不是玩家客户端或玩家存档。
- 模板由实际驯服的女仆捕获到铁剑后生成，包含真实压缩契约数据。
- 各压力样本使用独立 ItemStack、独立绑定标识和独立字节数组，不共享大载荷。
  女仆 UUID 沿用模板，仅测试数据与索引，不代表创建了同等数量的独立女仆。
- 内存测试同时保留武器对象和一份完整的损毁恢复快照，是双份驻留的压力模型。
  不是单个正常背包能携带的数量，也不是实际多人、网络同步或女仆 AI 容量。
- 512 KiB 试验在 1024 KiB 试验清理对象后使用同一 JVM；普通模板试验使用重启后的 JVM。

## 内存极限观测

| 模板 | 单把完整序列化大小 | 最后完成的武器＋恢复快照份数 | 下一份结果 |
|---|---:|---:|---|
| 普通契约模板 | 1605 B | 173207 | 内存分配失败 |
| 额外 512 KiB 独立档案数据 | 525914 B | 368 | 内存分配失败 |
| 额外 1024 KiB 独立档案数据 | 1050194 B | 183 | 内存分配失败 |

这是实际捕获到的 `OutOfMemoryError`，不是按序列化字节数推算。
测试任务捕获错误、清理对象后，堆使用回落到约 283–285 MiB；
但并发后台线程仍出现未处理的内存不足，RCON 监听等功能失效，不能认为服务器完全恢复。
已强制结束两个受影响的隔离服务器进程，未结束用户客户端。

序列化体积不等于实际 Java 堆占用。例如 1024 KiB 模式在 128 份时，
堆使用已经约 804 MiB；512 KiB 模式在 256 份时约 798 MiB。
没有将上述阈值线性外推到 4/6/8 GB 服务器。

64 KiB 模式未实际执行完成：上一轮耗尽内存使监听线程失效，后续请求无法运行。
没有为该模式填入估计数据。

## 后续方向

1. 优先控制恢复快照的累计内存，而不是给收藏武器数设一个任意上限。
2. 评估有限内存缓存＋独立磁盘快照，队列只保留轻量标识，分批按需读取。
   磁盘失败时也必须保留恢复来源，不能因超预算丢弃女仆。
3. 单物品数据上限需要结合正常女仆背包和联动数据样本调整；本次 2 MiB 上限
   本身不能阻止许多大载荷契约同时驻留。
4. 再单独测实际网络同步、多个在线玩家、保存重载，以及真实多女仆恢复。
   本轮不将这些未测场景算作通过。

## 复现注意

压力命令默认不注册。仅在独立测试目录、明确开启以下三个开关时可用：

```powershell
.\gradlew.bat --offline -I tmp/shrine-cached-dependencies.init.gradle runServer `
  '-PcompatRunDir=run-native-home-validation' '-PgalleryPreview=true' `
  '-PhomeLifeTest=true' '-PcontractStressTest=true'
```

控制台/RCON 命令：`contractinterior stress-contracts 0`、`512` 或 `1024`。
这些命令故意耗尽 1 GiB 测试 JVM 的内存，**不可用于玩家服务器或正式存档**。
测试类还拒绝在超过 1100 MiB 的最大堆中运行。
