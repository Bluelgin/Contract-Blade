# 黑狐战斗机制与职责

本页汇总当前战斗入口和责任分工，逐次调整稿保存在[黑狐历史目录](../archive/black-fox)。
不能将旧稿的站桩二阶段、挥刀振刀、10% 触发终核或旧伤害直接视为当前规则。

## 生命周期与攻击

神社入梦是统一入口，不要求 BladeTetra。入场、原刀托管、失败归还和离场恢复
沿用挑战会话；玩家路线见[神社与黑白狐](../player/FOXES.md)。
战斗使用技能池和低血量强化，原生完整 B1–B7、多轮次元突袭与远程技能共享场景调度。
最终核心由本体生命耗尽的路径触发，低血量本身不会提前进入终核。

## 防御与破势

防御入口采用拔刀剑原生精准格挡判定；挥刀及玩家连击 B 不再作为自动振刀。
只有指定技能的原生精准成功累计破势，同一技能轮次去重；普攻和反击不计数。
当前 `BlackFoxBalance` 要求五次成功，失衡持续 30 tick，普通命中不再额外加速恢复。
移除了 Boss 普通受击后的额外 16/8 tick 保护，原版受击保护及机制保护保留。

低于半血进入强化段后，在正常招间展开一次四角封缄阵。
四印存活时保护本体，击破全部刀印解除保护，不额外赠送失衡。
刀印连线只负责表现，不生成会爆炸的原版末影水晶。

## 责任边界

| 模块 | 负责内容 |
| --- | --- |
| `BlackFoxController` / 战斗状态 | 技能调度、状态切换与结束 |
| `BlackFoxGuardCompat` / 原生格挡 Mixin | 可选原生格挡桥与精准成功证据 |
| `BlackFoxAttackOrigin` / `BlackFoxParryCredit` / `BlackFoxBalance` | 来源、轮次去重与破势计数 |
| 技能执行器、原生时间线 | 真正攻击与预告节点 |
| `BlackFoxDamageTuning` / `BlackFoxCombatEvents` | 基础伤害和统一难度倍率 |
| 效果、网络与客户端镜头层 | 声音、粒子、血条及局部镜头反馈 |

兼容桥不写技能进度；客户端表现不判断伤害或精准成功。
难度配置只影响本场 Boss 对挑战者的伤害与新生成 Boss 的生命，
不影响玩家黑狐 SA。参数入口见[配置指南](../player/CONTRACT_CONFIGURATION.md)。

## 胜利与验证

最终核心击破并确认胜利后，先记录奖励，再执行十秒领域崩坏返程。
演出不造成伤害或破坏地形；返程失败沿用重试路径，不能重复发放奖励。
奖励 SA 的行为与上限见[剑核成长](BLACK_FOX_SWORD_CORE_GROWTH.md)，与 Boss 执行器分别维护。

原生夹具、单元测试和客户端视觉验收是不同层次，不能用静态检查替代实机结果。
历史执行证据及当前发布待验项见[验证索引](../validation/README.md)。
