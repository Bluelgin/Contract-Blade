# 誓约显现 1.0 / Oath Manifestation

## 玩家操作

女仆原生饰品栏装备「并契之环」，手持对应契约武器按 **O**（Minecraft 控制设置可修改），直接召唤并完全显现。也兼容已出战的唯一契约女仆直接进入完全显现。真实载体须仍在玩家库存中，共鸣严格大于零即可，无启动费用。缺少饰品时静默返回。

完全显现通过 `OathService.permitsSpirit` 提供严格绑定本次女仆、武器与选中剑灵的能力资格，黑狐、白狐、赤月原有授权仍负责身份、成长和冷却。不得修改物理驻留状态。普通显现继续暂停驻留能力，同契之证普通增伤仍暂停。对应契约技能的共鸣消耗由持续燃烧统一承担，燃烧自身不享受免除；结束后资格即时撤销。tooltip 保留原有纯爱台词。

戒指保留武器与护甲组合投影，不提供免耗。它与无尽契约按原生槽位顺序竞争终极能力；第一个终极饰品生效。普通投影依然按第一个投影饰品决定，万华御札判定独立。启动后摘戒指、交换饰品槽或换手持武器不会结束会话。

双方维持原生攻击和女仆 AI；默认玩家伤害 ×1.20、承伤 ×0.90，女仆伤害 ×1.30 且无敌。现有 60 tick 协奏窗口内双方命中同一敌对目标，第二击再 ×1.15，每目标至少 20 tick 一次，不额外调用 hurt 或支付共鸣。乘区顺序：攻击方强化／反噬，再计算受击玩家的减伤／反噬。

祭坛：同心结 + 灵魂水晶 ×2 + 下界合金锭 + 恶魂之泪 + 烈焰粉，消耗 1.0 P。

## 服务端配置

`serverconfig/maid_weapon-oath-server.toml`（每个世界；可用 defaultconfigs 部署）。

| 键 | 默认值 | 含义 |
| --- | ---: | --- |
| playerDamageBonus | 0.20 | 玩家伤害加成 |
| playerDamageReduction | 0.10 | 玩家承伤减少 |
| maidDamageBonus | 0.30 | 女仆伤害加成 |
| cooperationDamageBonus | 0.15 | 第二击额外乘区 |
| cooperationIntervalTicks | 20 | 每目标触发间隔 |
| poolFractionBurnedPerSecond | 0.025 | 每秒燃烧最大容量比例 |
| backlashDamageReductionPerLevel | 0.10 | 每级反噬造成伤害减少 |
| backlashDamageTakenPerLevel | 0.10 | 每级反噬承伤增加 |
| backlashDurationTicks | 3600 | 燃尽时反噬持续时间刷新值 |

默认 1000 上限每秒烧 25 点，满池约 40 秒。纳单位定点累计保留小数，服务器可改容量；灵脉和免耗不参与燃烧计算。一般能力仍可收费。资源 SavedData 的统一写入口拒绝燃烧池增量，自然恢复同时跳过该池并清理未兑现恢复小数；其他女仆池不受影响。包括显现期间的管理员资源增量调整也会被拒绝。

`oath_backlash` 使用原生 MobEffectInstance。每次燃尽等级加一，刷新持续时间；惩罚按最多五级，且输出减幅／承伤增幅均不超过 50%。同一玩家换女仆继续叠加。原生等级存储上限下最多显示 255 级；无自建层数计时。空治愈物品列表阻止牛奶和普通 curative items；原版死亡清除、到期消失。管理员 removeEffect 等特权不受拦截。

燃尽时 `OathRest` 按主人与女仆 UUID 单独记录休整，保存在 `OathSavedData.RestingMaids`，与载体和戒指无关。休整期间统一拒绝手动召唤、自动出战、原生转换及完全显现；其他女仆不受限制。每位女仆按配置的反噬时长独立计时，轮换燃尽不会延长前一位的休整；离线暂停，重连/重启保留。玩家死亡或反噬效果消失解除休整。归刃失败保留真实实体与现有恢复日志，在线期间每秒重试安全归刃，不创建替代实体。

## 权威与生命周期

- `ContractBaubleEffects.resolveSlots` 是 live／stored 和投影共享的槽位策略，stored NBT 按 Slot 索引恢复后解析，不信任列表顺序。
- `OathService` 只接受空激活意图；遍历真实库存，以 `ResonanceContract` 检查授权、绑定、载体、实体主人和唯一女仆。不会从客户端接受 UUID、余额或资格。
- `OathSavedData` 只保存 owner → binding/maid/active/remainder/最后结算原因，以及各女仆的未兑现燃烧小数；不复制女仆实体或共鸣池。
- 活跃会话每 START tick 复验实际载体和实体，按当前容量燃烧。饰品资格只在启动时检查。呼唤、普通 toggle 与新女仆显现被锁定。
- 唯一结束入口先写 inactive，随后尝试现有 forceRecall、燃尽时附加原生反噬，记录结果；嵌套召回不会重复结算。
- 断线、正常停服、跨维度、实体卸载／缺失、载体离开可解析范围或绑定失效采用**安全终止**：停止强化、尝试归刃，保留余额，不因中断施加反噬。重连不恢复强化，不追扣离线燃烧；持久化燃烧小数防止重连重置小数。
- 重启登录若发现未完成标记，通过相同入口终止，不凭旧状态生成实体或追加反噬。死亡结束不生成反噬，复活不恢复会话。
- 卸载、转移载体或归刃失败保留原恢复日志、实体存在标记和最近位置，由已有恢复机制处理；不复制实体／旧快照，不为未知卸载强造女仆。日志输出 `Oath ended ... reason=... recalled=...`。

## 伤害兼容边界

`OathCombat` 在 Forge LivingAttack 最高优先级拒绝女仆伤害，早于护甲／吸收消耗；LivingHurt 再作防线。在既有 LivingHurt 上修改金额一次，不写永久属性、不发第二次伤害、不修改取消状态。

玩家强化依据服务端 DamageSource 的真实 causing entity，原生 Projectile 的 owner 必须一致，独立于当前手持物。非原生间接来源仅使用已有 ContractCombatCredits 证明。没有可靠归因的来源不猜主人。延迟投射物在命中时按当时会话计算，结束后飞到的弹丸不保留旧强化。

赤月的 SoulDamageEngine 结算已经基于原伤害与合法债务，跳过再次攻击方放大／反噬，避免重复修改债务；受击玩家的防御／反噬仍正常。已验证原生单次限伤按上限截断；若已有滚动限伤或保护阶段在 Forge 之前结算，保留其原输入，不在预算之后追加正向增益。普通的后续 Forge 限伤监听仍可继续削减／取消。

不保证绕开 Forge 事件的直接改血、未知 Boss 的专用 HP、未知的事件前限伤和所有枪包脚本。未对这些能力增加全局 Mixin、强制解取消或改写生命。特别是未知事件前限伤的加成位置需要针对实际版本验证；这不等同于已验证所有第三方 Boss。

## HUD 与美术

`OathNetwork` 只发启动／结束的女仆身份和 active 状态；`ResonanceNetwork` 继续负责余额快照。现有 MaidFavorabilityOverlay 优先取会话身份，换成任何武器也显示对应池。火焰、25% 以下闪烁和结束 30 tick 余烬／灰烬由客户端时间推导，无每 tick 动画包和新 Shader。

原创 SVG／PNG 源码位于 `art/oath`，`python art/oath/export.py` 通过 Inkscape 可重建；没有 AI 位图或外部美术。

## 验证与实机清单

`OathBurnTest` 验证不同容量的 800 tick 比例、保存小数、配置变化、小池最低燃烧速率和反噬五级上限。

`OathValidation` 复用现有共鸣专服夹具入口（`-PresonanceTest=true`，一次性世界），验证真实 TLM 槽位／存储、1/0 启动、戒指移除后继续、资源恢复阻止、女仆真实 hurt 不扣血甲、受控 Forge 事件伤害计算、协奏频率、其他池恢复、40 秒燃尽、多女仆反噬、牛奶接口、异常终止和重复结束。它用 FakePlayer 与部分直接事件调用验证服务端行为，不能冒称真实联网玩家战斗录像。

仍需手动验收：

1. 客户端 O 键重绑定、1 点启动即时音画、各 GUI 缩放下燃烧／低共鸣／结束灰烬。
2. 持原版剑、SlashBlade 和 TACZ 实际射击／延迟弹丸时的强化和 HUD；逐一检查实际 Boss 限伤版本。
3. 女仆 AI 保持原工作模式，挨打不消耗护甲、吸收或触发濒死收回。
4. 真实网络断线／重连、停服重启、玩家死亡／复活、区块卸载及载体移入外部容器时的安全恢复。
5. 牛奶不能解除、自然到期解除、死亡正常清除，轮换多名女仆叠级而惩罚封顶。

CI 结果与未运行项目见 PR #34 的最新说明；只有日志中出现 `OATH_NATIVE_PASS` 才将专服夹具标为通过。没有图形客户端誓约显现的实机验收声明。
