# 数据、网络、恢复与性能审读

这些结论来自当前#38实际实现，除注明的夹具外不表示做过崩溃/性能验收。

|边界|已经存在的实现|仍需补齐与验收|
|---|---|---|
|物品权威|不可变 ContractReference/ContractChannels，persistent Codec及必要StreamCodec；intrinsic最多64，选择/身份/混合/旧票校验；完整女仆快照不放物品也不发HUD|Schema升级、正式契约独立设置完整覆盖、所有入口的持有者/主人/载体校验；未知未来数据保留并拒绝写入|
|实体关联|`maid_binding` UUID附件通过原生序列化，lifecycle核对账本/主人/绑定；不是附件自行授予权威|死亡、重生、跨维度/卸载重载与第三方实体复制组合，不能把附件持久化本身当作语义验证|
|持久化职责|NativeContractStore仍合并阶段/身份与大快照；resonance、mastery、spirit vein、oath/cooldown各SavedData；journal备份转移意图|先测真实记录体积与写入频率，再决定快照/低频身份分离；不用假想规模强加分片框架；成长/余额恢复不得重置|
|普通支付与恢复写入|NativeResonanceSavedData只改池并setDirty；NativeRecoveryTick每20tick扫描在线玩家背包/菜单carried，按女仆去重，512活动上限，不是每tick遍历整个契约账本/序列化全女仆|全部技能费用/自定义规则接入；多玩家与大背包实际采样，活动session失效/长期缓存和边界公平性仍须检查；setDirty不是立即磁盘提交|
|转移日志/检查点|NativeTransferJournal转移写入使用文件force+原子替换和目录force；snapshot在捕获/转移路径。NativeCheckpointService在显式checkpoint/停服候选中调用saveEverything，再写checkpoint|不能描述成每次普通攻击都fsync；也不能保证停服无卡顿。测连续捕获/多大快照/停服延迟、Windows文件系统与失败隔离。不要为优化删安全边界，也不要扩大为每tick强刷|
|正常重启|真实两进程、同世界、正常停服重启夹具验证物品/余额/旧票拒绝|不是跨文件ACID或断电证明。pending/旧LIVE/未知状态需诊断隔离，不能把未加载视作不存在；逐事务阶段故障注入、旧载体副本、掉落物/玩家文件不同步尚缺|
|恢复/遗失|NativeLiveReconciliation只能确认匹配且已加载的LIVE实体，不创建第二只；未知记录拒绝|正式遗失武器、解绑/迁居/重生、可诊断隔离与安全领回尚未实现完整流程；不能宣传全生命周期完成|
|网络|status_request/oath_toggle为无身份输入请求；服务器从主手载体派生权限并检查线程；10tick限流；status最大1,000,000单位、固定字段/票据，3秒缓存、弱引用map；无快照广播|目前仍周期请求/回复，未完整实现按变化推送；正式轮盘/菜单/技能payload需分别限量/限频、世界/死亡/退出缓存失效；HUD maximum目前取DEFAULT，完整用户配置适配未完|
|战斗/视觉上限|尚无Neo黑狐/赤月/万华完整执行器|不能因当前实体少就宣称正式性能优秀。完成后测多人高频技能实体/粒子上限、命中窗口/队列清理、网络量、GPU绘制与对象分配；完整内部空间需按需卸载区块|
|旧世界导入|存在探索性旧快照编码，不是完整ForgeCaps/物品组件/世界转换器|显式工具、真实旧样本、备份、Schema区分/幂等/重复拒绝、嵌套第三方物品和空间实例；未支持正式世界无缝升级|
